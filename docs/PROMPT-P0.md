# Задача: реализовать P0 — встроенный SSH-терминал для «SSH Control»

Ты работаешь в проекте **SSH Control** — это настольное Electron-приложение для macOS (хранилище SSH-ключей, данных серверов и псевдонимов `~/.ssh/config`). Твоя задача — реализовать этап **P0** из дорожной карты: встроенный терминал вместо запуска внешнего Terminal.app.

Следуй инструкции точно. Если что-то неоднозначно — выбери наиболее простое и надёжное решение, сохрани существующую архитектуру и стиль кода.

---

## 0. Нормативные документы и инварианты (обязательно)

Прежде чем писать код, прочитай целиком и следуй этим документам — это норматив проекта, а не рекомендации:
- **`AGENTS.md`** — что делает проект, стек, модель безопасности, ограничения платформы.
- **`CODE-RULES.md`** — как писать код: слои (main/preload/renderer), IPC, хранилище, чистый код, конвенции plain-JS, безопасная разработка (§8), тесты (§9), лимит ≤700 строк на файл.
- **`UI-RULES.md`** — как делать интерфейс: токены/темы (§1), грамматики экранов (терминал — §4.7), переиспользуемые классы (§5), доступность (§7), скелет до кода (§9.1) и чек-лист перед сдачей (§9.2).
- **`WORKFLOW-RULES.md`** — процесс: задачи в GitHub (Issues/PR), декомпозиция, DoD (§4), ревью по факт-протоколу (§3), milestone `P0 — встроенный терминал`.

При конфликте этих документов с этим промтом или с твоим вкусом — побеждают они.

**Инварианты, которые нельзя нарушать (AGENTS.md + CODE-RULES §8):**
1. **Приватный материал ключей не покидает main-процесс.** Через IPC в рендер — только метаданные. Пароль сервера и парольная фраза ключа через IPC не передаются никогда: в P0 они вводятся пользователем прямо в PTY-терминал.
2. **`contextIsolation: true`, `nodeIntegration: false`, CSP `script-src 'self'` не ослабляются.** Никаких CDN, inline-скриптов, `eval`, `new Function`, `unsafe-inline`.
3. **Секреты не в git, не в логах, не в сообщениях об ошибках.** Не логировать пароли/фразы/ключи и содержимое `data.json`.
4. **Внешние команды — через `execFile`/`spawn` с массивом аргументов**, не через `exec` со строкой оболочки (защита от инъекции). `extraArgs` разбивается и добавляется отдельными аргументами.
5. **Пути из пользовательского ввода санитизируются** до превращения в путь; `~/.ssh/config` правится только управляемыми `Host`-блоками, чужой контент сохраняется verbatim.

**Ограничения платформы (AGENTS.md):**
- Без бандлера: зависимости рендера — локальные файлы внутри `renderer/`; `node_modules` в собранное `.app` не входит.
- Нативные модули (node-pty) — собраны под версию Electron (`electron-builder install-app-deps` / `@electron/rebuild`).

## 1. Контекст проекта (уже реализовано, изучи перед правкой)

**Стек:** Electron 45, без бандлера (рендер грузит обычный `app.js`), macOS, `contextIsolation: true`, `nodeIntegration: false`, `sandbox: false`.

**Структура:**
- `main/main.js` — точка входа, регистрирует IPC через `ipcMain.handle(...)`.
- `main/preload.js` — мост `window.api` через `contextBridge.exposeInMainWorld` (каждый метод — `ipcRenderer.invoke`).
- `main/services/` — модули: `keys.js`, `sshConfig.js`, `storage.js`, `connect.js`.
- `renderer/index.html`, `renderer/styles.css`, `renderer/app.js` — интерфейс.

**Как рендер обращается к main:** `const bridge = window.api;` (см. `renderer/app.js:3`). Все новые методы добавляй в `preload.js` и регистрируй в `registerIpc()` в `main.js`.

**Модель сервера** (`state.data.servers`, файл `data.json`):
```js
{ id, name, group, host, port, user, authMethod: 'key'|'password', keyPath, password, color, notes, extraArgs }
```
**Псевдоним** (`~/.ssh/config`, Host-блок) из `sshConfig.listHosts()`:
```js
{ name, names, hostName, user, port, identityFile, extraCount }
```

**Готовое в `main/services/connect.js`** (переиспользуй, не дублируй логику):
- `buildCommand(server)` — собирает строку `ssh ...` (порт, `-i ключ`, `IdentitiesOnly`, доп. аргументы, `user@host`).
- `buildAliasCommand(alias)` — `ssh alias`.
- `runCommand(cmd)` — сейчас запускает Terminal.app через `osascript`. **Для терминала это НЕ нужно** — см. раздел 4.

**Важное ограничение — CSP** в `renderer/index.html:5`: `default-src 'self'; script-src 'self'`. Никаких CDN. Все JS/CSS терминала должны быть локальными файлами и попадать в собранное приложение.

**Сборка** (`package.json`, electron-builder): в `build.files` включены только `main/**/*`, `renderer/**/*`, `package.json`. `node_modules` в сборку НЕ входит. Поэтому всё, что использует рендер, должно лежать внутри `renderer/` (или быть явно добавлено в `build.files`).

## 2. Цель (объём P0)

Добавить встроенный SSH-терминал, чтобы подключение к серверу/псевдониму открывалось **внутри приложения**, а не в отдельном Terminal.app.

Конкретно реализовать:
1. Встроенный терминал на **xterm.js** (полная VT-эмуляция, скроллбэк, копирование/вставка).
2. **Вкладки** — несколько одновременных SSH-сессий, закрытие вкладки, индикатор состояния.
3. **Подключение** прямо из карточек «Серверы» и «Псевдонимы»: кнопка «Подключиться» открывает вкладку терминала и стартует `ssh`.
4. **Поиск по выводу с поддержкой regex**.
5. **Темы/цветовые схемы** терминала (согласованы со светлой/тёмной темой приложения; truecolor).

## 3. Детальные требования

### 3.1 Новый раздел «Терминал»
- Добавь в сайдбар пункт навигации **«Терминал»** (рядом с «Ключи», «Псевдонимы», «Серверы», «Настройки») и новую секцию `view-terms` в `index.html`.
- В разделе: **панель вкладок** (сверху) + область терминала (внизу). Поддерживай пустое состояние («Нет открытых сессий — подключитесь к серверу или псевдониму»).
- Каждая вкладка содержит свой экземпляр xterm.js. Заголовок вкладки = имя сервера / псевдонима, кнопка «×» закрывает вкладку (и завершает процесс).
- **Интерфейс — по `UI-RULES.md`** (грамматика терминала описана в §4.7). Оформление только токенами из `styles.css`; тёмная тема — переопределение тех же токенов; статусные цвета (подключено/завершено/ошибка) — существующими или новыми статусными токенами, не произвольными hex.
- **Скелет до кода** (`UI-RULES.md` §9.1): сначала составь текстовый скелет экрана терминала (какие панели/контролы + явный список «чего на экране нет»). Приведи его в отчёте как шаг 1; если подтверждения владельца нет, иди по задокументированному скелету и отметь открытые вопросы.
- **Доступность** (`UI-RULES.md` §7): иконки-кнопки с `aria-label` + `title`, видимый фокус, контраст AA в обеих темах.

### 3.2 Подключение из карточек
- В списке серверов кнопка «Подключиться» и в списке псевдонимов «Подключиться» теперь должны **открывать вкладку терминала** и запускать SSH-сессию, а не вызывать Terminal.app.
- Сохрани существующую возможность «копировать команду» (если она есть) без изменений.
- Авторизация:
  - `authMethod: 'key'` — ssh использует ключ (как сейчас в `buildCommand`).
  - `authMethod: 'password'` — пользователь вводит пароль **прямо в терминале** по интерактивному запросу ssh (реальный PTY это обеспечивает). Никакого автозаполнения пароля в P0.
  - Ключ с парольной фразой — фраза тоже вводится в терминале.
- После запуска фокус на новую вкладку; заголовок вкладки = `server.name || server.host` (для псевдонима — `alias`).

### 3.3 Терминал (xterm.js)
- Используй **xterm.js** + аддоны `fit` (подгонка под размер контейнера) и `search` (поиск). Устанавливай через `npm i xterm @xterm/addon-fit @xterm/addon-search`.
- **Скроллбэк**, выделение текста мышью, копирование (Cmd+C) / вставка (Cmd+V) должны работать «из коробки».
- Пересчитывай размер терминала при изменении окна/контейнера (fit + отправка новых `cols/rows` в main).
- Лигатуры/truecolor — настройки по умолчанию xterm.js (24-bit цвет включён).

### 3.4 Поиск с regex
- Кнопка/поле поиска в разделе терминала: поиск по текущей вкладке с переключателем «regex».
- Реализуй через `@xterm/addon-search` (`findNext`, опция `regex`). Подсветка найденного, Enter — далее, Esc — закрыть.

### 3.5 Темы
- Поле/селектор темы терминала в разделе терминала с несколькими пресетами (минимум: «Светлая», «Тёмная», «Система/авто»).
- Тема терминала по умолчанию согласована с темой приложения (см. `state.data.settings.theme`: `system|light|dark`).
- Сохраняй выбранную тему терминала в `data.settings.terminalTheme` (через существующий `bridge.save`).
- Подбери читаемые цветовые палитры (фон/текст/ANSI-цвета) для светлой и тёмной схем.

## 4. Технические указания (обязательно)

### 4.1 Реальный PTY через node-pty
Встроенный `ssh` **требует PTY** (интерактивные запросы пароля/фразы, full-screen программы). Поэтому:
- Установи **`node-pty`** (`npm i node-pty`) и используй его в **main-процессе** (новый модуль `main/services/terminal.js`).
- **Внимание:** node-pty — нативный модуль; он должен быть собран под твою версию Electron. Если `npm i` не подтянул готовый prebuilt, собери через `@electron/rebuild` (или `electron-builder install-app-deps`). Проверь, что приложение запускается после установки (`npm start`).
- Если нативная сборка node-pty окажется заблокированной — НЕ переделывай всё молча: сообщи об этом в итоговом отчёте и предложи запасной план (чистый `ssh2`), но сначала попробуй node-pty.

### 4.2 Модуль `main/services/terminal.js`
Создай модуль, управляющий сессиями node-pty. Примерный контракт:
```js
createSession({ command, cols, rows }) -> { id }   // spawn pty с командой ssh
write(id, data)                                    // pty.write(data)
resize(id, cols, rows)                             // pty.resize(...)
kill(id)                                           // pty.kill(); удалить сессию
killAll()                                          // при выходе из приложения
```
- Команду `ssh` строй **через существующий `connect.js`** (`buildCommand` / `buildAliasCommand`) — не дублируй сборку команды.
- node-pty требует команду + **массив аргументов** (без оболочки). Добавь в `connect.js` чистую функцию `buildArgs(server)` (возвращает `string[]`), переиспользуй её и в `buildCommand` (для отображения/копирования), и в `terminal.js` (для spawn). Покрой `buildArgs`/`buildCommand` unit-тестом `node:test` (CODE-RULES §9.1).
- События наружу: `data` (id, строка) и `exit` (id, code). Пробрасывай их в рендер через `mainWindow.webContents.send('term:data', ...)` / `send('term:exit', ...)`.
- При закрытии окна приложения (или `app.quit`) вызывай `killAll()`.

### 4.3 IPC и preload
Добавь в `main.js` в `registerIpc()`:
- `ipcMain.handle('term:create', (_e, payload) => ...)` — payload: `{ type:'server', server }` или `{ type:'alias', alias }`, плюс `cols/rows`.
- `ipcMain.handle('term:write', (_e, id, data) => ...)`
- `ipcMain.handle('term:resize', (_e, id, cols, rows) => ...)`
- `ipcMain.handle('term:kill', (_e, id) => ...)`

В `preload.js` добавь соответствующие методы `window.api`:
```js
createTerminal: (payload) => ipcRenderer.invoke('term:create', payload),
writeTerminal: (id, data) => ipcRenderer.invoke('term:write', id, data),
resizeTerminal: (id, cols, rows) => ipcRenderer.invoke('term:resize', id, cols, rows),
killTerminal: (id) => ipcRenderer.invoke('term:kill', id),
onTermData: (cb) => { ipcRenderer.on('term:data', (_e, id, data) => cb(id, data)); },
onTermExit: (cb) => { ipcRenderer.on('term:exit', (_e, id, code) => cb(id, code)); }
```
Соблюдай существующий нейминг `пространство:действие` и стиль `main.js`/`preload.js`.

### 4.4 Доставка xterm.js в рендер (без бандлера + CSP `script-src 'self'`)
Это критично, потому что в проекте нет сборщика:
- **Нельзя** использовать CDN (заблокировано CSP) и **нельзя** полагаться на `node_modules` в проде (не попадает в `build.files`).
- Приемлемый способ: скопировать готовые браузерные (UMD/IIFE) сборки `xterm.js` и аддонов `fit`/`search` вместе с `xterm.css` в **`renderer/vendor/`** и подключить их `<script src="vendor/...">` / `<link rel="stylesheet" href="vendor/xterm.css">` в `index.html`.
- Если готовых UMD-файлов в свежем xterm нет (пакет перешёл на ESM/CJS), сбандли их одним файлом в IIFE (например, через esbuild: `npx esbuild renderer/term-entry.js --bundle --outfile=renderer/vendor/xterm.bundle.js --format=iife --global-name=TerminalBundle`), а результат положи в `renderer/vendor/`.
- Итог: `renderer/vendor/` содержит всё необходимое и попадает в сборку (уже покрывается правилом `renderer/**/*`).

### 4.5 Рендер (`renderer/app.js` + `styles.css`)
- Следуй существующему стилю кода: `const $ = ...`, `esc()`, `toast()`, обработчики через `data-action`, `state`.
- Добавь управление вкладками терминала и обработчики событий `onTermData`/`onTermExit`.
- На `term:exit` покажи в вкладке плашку «Сессия завершена (код N)» и не падай; закрытие вкладки вызывает `killTerminal`.
- **Лимит ≤700 строк на файл** (CODE-RULES §1): не раздувай `app.js` (он уже у порога). Вынеси логику терминала в отдельный `renderer/terminal.js`, подключи его `<script src="terminal.js"></script>` после `app.js`; общие `state` и хелперы (`$`, `esc`, `toast`) доступны глобально из `app.js`.
- Заголовки вкладок (имя сервера/псевдонима) — только через `esc()`/`textContent` (CODE-RULES §4.2). Вывод ssh идёт в xterm, а не в HTML, поэтому XSS-экранирование к нему не применяется.
- Новые переиспользуемые элементы (панель вкладок, область терминала) — классы в `styles.css`, не inline-стили (исключение — только цвет категории из данных).

- [ ] Закрытие вкладки завершает ssh-процесс; закрытие приложения не оставляет «висячих» ssh-процессов.

- [ ] DoD пройден (WORKFLOW-RULES §4.1): секреты не в git/логах, команды — массивом аргументов, текст экранирован, CSP и границы процесса не ослаблены; UI-чеклист `UI-RULES.md` §9.2 выполнен.

## 6. Как проверить

1. `npm start`.
2. Создай/выбери сервер с методом входа «Ключ» → «Подключиться» → должен открыться встроенный терминал и войти.
3. Повтори для псевдонима.
4. Открой 2–3 вкладки одновременно, проверь переключение и закрытие.
5. Проверь поиск с regex (например, `\d{3}`) и тему.
6. `npm run package`, запусти `.app` из `dist/`, повтори шаги 2–5.
