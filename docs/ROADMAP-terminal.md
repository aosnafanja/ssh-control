# Дорожная карта: встроенный терминал для SSH Control

> Приоритизированный список функций встроенного терминала на основе исследования конкурентов ([TERMINALS-RESEARCH.md](TERMINALS-RESEARCH.md) и [RESEARCH.md](RESEARCH.md)).
>
> Легенда приоритетов: **P0** — обязательно для MVP, **P1** — важно (следующая итерация), **P2** — дифференциаторы/позже.
> Трудоёмкость: **S** — < 1 недели, **M** — 1–3 недели, **L** — 1–2 месяца, **XL** — 2+ месяца (оценка для одного разработчика, Electron + xterm.js).
>
> **Статус:** P0 и P1 закрыты; текущий этап — **P2 «Дифференциаторы»**. P1-хвост (3 функции) — в бэклоге.

## P0 — Гигиенический минимум (MVP терминала)

| # | Функция | Трудоёмкость | Зачем / что даёт |
|---|---------|--------------|------------------|
| 1 | **Встроенный терминал (xterm.js)** — полноценная VT-эмуляция, копирование/вставка, скроллбэк | L | База. Убирает запуск внешнего Terminal.app — главное ожидание от SSH-клиента |
| 2 | **Вкладки** | S | Стандарт всех популярных терминалов (есть у iTerm2, Windows Terminal, Ghostty, kitty, WezTerm) |
| 3 | **Подключение прямо из карточки сервера** — `ssh` внутри терминала по сохранённым данным (хост/порт/пользователь/ключ) | M | Связывает хранилище серверов с терминалом; без этого терминал бесполезен |
| 4 | **Поиск по выводу с regex** | S | Ценится повсеместно; iTerm2/kitty/WezTerm/Ghostty/Warp — у всех есть |
| 5 | **Темы / цветовые схемы** (вкл. truecolor, лигатуры) | S | «Гигиенический минимум» эстетики; сотни тем у Ghostty, темы у WT/Warp/Tabby |

**Итог P0:** рабочий встроенный терминал, в котором можно открыть сессию из карточки сервера, работать во вкладках, искать и настраивать тему. Трудоёмкость ≈ L + 2×S + M.

## P2 — Дифференциаторы (третья итерация)

> **Текущий этап.** Ниже — план; эпик и задачи создаются по мере старта.

| # | Функция | Трудоёмкость | Зачем / что даёт |
|---|---------|--------------|------------------|
| 13 | **SFTP-файловый менеджер** (панель drag-and-drop) | L | Ожидаемая пара к SSH; есть у Termius, Royal TSX, SecureCRT, electerm, WindTerm |
| 14 | **Портовые туннели / port forwarding** (local/remote/dynamic) | L | Есть почти у всех; расширяет сценарии до работы с инфраструктурой |

## Сводная оценка

| Этап | Объём | Что получаем |
|------|-------|--------------|
| P0 | ≈ 2–3 недели | Рабочий встроенный терминал (база) |
| P1 | ≈ 3–5 недель | Полноценный SSH-клиент уровня Tabby/electerm |
| P2 | ≈ 2–3 месяца | Дифференцированный продукт с AI/MCP |

**Ключевая рекомендация:** не строить весь терминал «с нуля» — использовать **xterm.js** (та же база, что у Tabby/electerm/VSCode) и сосредоточить усилия на **связке терминала с уже существующим хранилищем ключей и `~/.ssh/config`** — это то, чего нет у iTerm2/Ghostty и что напрямую продолжает текущее УТП SSH Control.
